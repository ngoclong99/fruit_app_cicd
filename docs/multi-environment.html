3. Quan ly secrets — 3 lop

Lop 1 — May local (chi ban biet) backend/.env ← DB local, chay docker-compose up frontend/.env.local ← VITE_API_URL=http://localhost:5000 Lop 2 — GitHub Secrets (infra keys, it thay doi) AWS_ACCESS_KEY_ID ← credentials cua github-actions-deploy AWS_SECRET_ACCESS_KEY ← credentials cua github-actions-deploy ECR_REGISTRY ← URL kho Docker images tren AWS EC2_HOST ← IP cua EC2 (trong Environment secrets) EC2_SSH_KEY ← SSH key vao EC2 (trong Environment secrets) Lop 3 — AWS Parameter Store (app secrets, them/sua tu do) /myapp/production/DB_NAME /myapp/production/DB_PASSWORD /myapp/production/NGINX_HTTP_PORT = 80 /myapp/staging/DB_NAME /myapp/staging/NGINX_HTTP_PORT = 8080 ...

  --value "jwt_secret_cua_ban" \
  --type SecureString

4.4 Cach workflow fetch secrets

Trong deploy.yml, buoc "Fetch secrets from Parameter Store" lam viec nhu sau: 

aws ssm get-parameters-by-path \
  --path "/myapp/production/" \      # Lay tat ca keys trong thu muc nay
  --with-decryption \                 # Giai ma SecureString
  --query "Parameters[*].[Name,Value]" \
  --output text | \
awk -F'\t' '{n=split($1,a,"/"); print a[n]"="$2}' > backend/.env
# awk: tach lay phan cuoi cua path lam ten bien
# /myapp/production/DB_NAME → DB_NAME=todos_db
# /myapp/production/DB_PASSWORD → DB_PASSWORD=xxx
# Ket qua: tao file backend/.env voi day du tat ca keys
Them key moi chi can 1 buoc Them parameter vao SSM → deploy lan sau tu dong co key do trong .env — khong can sua bat ky file code nao.

5. GitHub Environments — Giai thich chi tiet

5.1 GitHub Environments la gi?

GitHub Environments cho phep nhom secrets + rules rieng cho tung moi truong. Khi job deploy chay, no biet dang deploy moi truong nao va lay dung secrets cua moi truong do.

GitHub Environments ├── production │ ├── Required reviewers: ngoclong99 ← phai approve moi deploy │ └── Secrets: │ EC2_HOST = 13.229.216.57 │ EC2_SSH_KEY = -----BEGIN RSA... │ ├── staging │ └── Secrets: │ EC2_HOST = 13.229.216.57 ← cung EC2, khac moi truong │ EC2_SSH_KEY = -----BEGIN RSA... │ └── development └── (trong rong, chay local)

5.2 Required reviewers (production)

Khi Required reviewers duoc bat cho environment production:

  • Push len main → build chay binh thuong
  • Truoc buoc deploy production → GitHub dung lai, gui thong bao
  • Ban (nguoi reviewer) vao GitHub Actions → bam Review deployments → Approve
  • Deploy moi chay tiep
Tai sao can approve? Dam bao khong ai deploy nham len production. Nen chi 1 nguoi co quyen approve. Voi team nho co the de chinh minh lam reviewer — van can bam approve thu cong.

5.3 Environment URL (APP_URL variable)

Trong deploy.yml co dong:

environment:
  name: ${{ needs.build.outputs.environment }}
  url:  ${{ vars.APP_URL }}   # Hien thi link truy cap tren GitHub Actions UI

Them APP_URL vao Environment variables (khong phai secrets) thi sau moi deploy GitHub hien thi nut link truc tiep den app:

  • production: http://13.229.216.57
  • staging: http://13.229.216.57:8080

6. deploy.yml — Giai thich tung buoc

6.1 Job 1: Build

on:
  push:
    branches: [develop, staging, main]
# Workflow chay khi push len bat ky 3 branch nay

- name: Determine environment from branch
  run: |
    case "${{ github.ref_name }}" in
      main)    echo "environment=production"  >> $GITHUB_OUTPUT ;;
      staging) echo "environment=staging"     >> $GITHUB_OUTPUT ;;
      *)       echo "environment=development" >> $GITHUB_OUTPUT ;;
    esac
# Doc ten branch → map sang ten moi truong
# main    → production
# staging → staging
# khac    → development
# Luu vao GITHUB_OUTPUT de cac buoc sau dung duoc

- name: Set image tag (branch + git short SHA)
  run: echo "tag=${{ github.ref_name }}-${GITHUB_SHA::7}" >> $GITHUB_OUTPUT
# Tao tag duy nhat cho moi commit: staging-abc1234
# github.ref_name = ten branch (staging, main...)
# GITHUB_SHA::7  = 7 ky tu dau cua commit hash
# Vi du: main-a1b2c3d, staging-x7y8z9w
# → De rollback: chi can doi lai IMAGE_TAG ve tag cu

- name: Fetch VITE_API_URL from Parameter Store
  run: |
    VITE_API_URL=$(aws ssm get-parameter \
      --name "/myapp/${{ steps.env.outputs.environment }}/VITE_API_URL" \
      --with-decryption \
      --query "Parameter.Value" \
      --output text)
    echo "VITE_API_URL=$VITE_API_URL" >> $GITHUB_ENV
# Lay VITE_API_URL tu SSM truoc khi build frontend
# Vi URL khac nhau theo moi truong:
#   production: http://13.229.216.57
#   staging:    http://13.229.216.57:8080
# >> $GITHUB_ENV: luu vao bien moi truong de buoc sau dung

- name: Build & push frontend
  run: |
    docker build \
      --build-arg VITE_API_URL=$VITE_API_URL \   # Truyen vao luc build
      -t $ECR_REGISTRY/myapp-frontend:${{ steps.tag.outputs.tag }} \
      ./frontend
# VITE_API_URL duoc nhung thang vao bundle JS luc build
# → moi moi truong co bundle khac nhau voi URL khac nhau

6.2 Job 2: Deploy

deploy:
  environment:
    name: ${{ needs.build.outputs.environment }}
# Khai bao se deploy len moi truong nao
# GitHub tu dong lay secrets cua moi truong do (EC2_HOST, EC2_SSH_KEY)
# Neu environment=production va co Required reviewers → doi approve

- name: Fetch secrets from Parameter Store
  run: |
    aws ssm get-parameters-by-path \
      --path "/myapp/${{ needs.build.outputs.environment }}/" \
      --with-decryption \
      --query "Parameters[*].[Name,Value]" \
      --output text | \
    awk -F'\t' '{n=split($1,a,"/"); print a[n]"="$2}' > backend/.env
    echo "PORT=5000" >> backend/.env
    echo "ENVIRONMENT=${{ needs.build.outputs.environment }}" >> backend/.env
# Lay TAT CA keys trong /myapp/staging/ hoac /myapp/production/
# Convert thanh dinh dang KEY=VALUE roi ghi vao backend/.env
# File .env nay se duoc SCP len EC2

- name: Copy config files to EC2
  with:
    target: ~/app/${{ needs.build.outputs.environment }}
    # 1 EC2: deploy vao thu muc rieng
    #   main    → ~/app/production/
    #   staging → ~/app/staging/
    # Neu 3 EC2 rieng: doi thanh "target: ~/app"

script: |
  cd ~/app/${ENVIRONMENT}
  docker compose -p myapp-${ENVIRONMENT} -f docker-compose.prod.yml pull
  docker compose -p myapp-${ENVIRONMENT} -f docker-compose.prod.yml up -d
  # "-p myapp-${ENVIRONMENT}": project name de namespace
  # Container production: myapp-production-backend-1
  # Container staging:    myapp-staging-backend-1
  # Volume production:    myapp-production_postgres_data
  # Volume staging:       myapp-staging_postgres_data
  # → Khong container nao dung chung ten → khong xung dot

7. docker-compose.prod.yml — Giai thich tung buoc

nginx:
  ports:
    - "${NGINX_HTTP_PORT}:80"
# NGINX_HTTP_PORT den tu SSM (da ghi vao backend/.env)
# production: NGINX_HTTP_PORT=80  → map port 80  cua EC2 vao port 80  cua container
# staging:    NGINX_HTTP_PORT=8080 → map port 8080 cua EC2 vao port 80  cua container
# Ben trong container nginx van nghe port 80
# Chi khac o port phia ngoai (EC2)

pgadmin:
  ports:
    - "${PGADMIN_PORT}:80"
# Tuong tu:
# production: 5050:80 → http://13.229.216.57:5050
# staging:    5051:80 → http://13.229.216.57:5051

volumes:
  postgres_data:
# Docker Compose tu them prefix tu project name:
# -p myapp-production → volume: myapp-production_postgres_data
# -p myapp-staging    → volume: myapp-staging_postgres_data
# => Data production va staging doc lap, khong loi vao nhau

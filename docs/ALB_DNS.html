1. DNS căn bản (5 phút đọc)

DNS = danh bạ của internet

Người ta không nhớ 54.179.253.43, người ta nhớ vhnlong.store. DNS làm việc dịch ngược lại:

Browser: "vhnlong.store la IP gi?" │ ▼ DNS resolver (cua ISP): "8.8.8.8, biet khong?" │ ▼ 8.8.8.8 (Google DNS): "Hoi root DNS -> .store DNS -> Route53 cua vhnlong" │ ▼ Route 53: "vhnlong.store -> 54.179.253.43" │ ▼ Browser: TCP connect 54.179.253.43:443

Các loại DNS record phổ biến

LoạiMap từMap sangKhi nào dùng
AdomainIPv4 (vd 54.179.253.43)Web cơ bản, server có IP tĩnh hoặc bạn tự update
AAAAdomainIPv6Tương tự A nhưng IPv6
CNAMEsubdomaindomain khác (vd www → vhnlong.store)Alias subdomain, không dùng cho root domain
ALIAS (Route 53 đặc biệt)domainAWS resource (ALB, CloudFront, S3 site)Khi target là AWS, dùng ALIAS thay A vì AWS tự lo IP
MXdomainmail serverNhận email (Gmail business, Zoho...)
TXTdomainchuỗi text bất kỳSPF, DKIM, domain verification (Google, Stripe...)

TTL (Time To Live)

Sau khi resolver lấy IP từ Route 53, nó cache lại trong N giây để lần sau không phải hỏi lại. TTL=60 = cache 60 giây.

  • TTL thấp (60s): đổi IP nhanh có hiệu lực toàn cầu, nhưng resolver phải hỏi Route 53 nhiều hơn → Route 53 tính tiền nhiều hơn (tuy vẫn rất rẻ)
  • TTL cao (3600s = 1h): rẻ + nhanh cho user nhưng đổi IP phải đợi cả tiếng
  • Project bạn dùng TTL=60 vì IP đổi mỗi sáng

2. Route 53 trong project hiện tại

Route 53 là DNS service của AWS. Trong project bạn:

# Lay hosted zone hien tai
aws route53 list-hosted-zones --query "HostedZones[?Name=='vhnlong.store.']"
# Id: /hostedzone/Z0999500HD1JE8VHHDN2

# Liet ke tat ca record
aws route53 list-resource-record-sets --hosted-zone-id Z0999500HD1JE8VHHDN2 `
  --query "ResourceRecordSets[].[Name,Type,TTL,ResourceRecords[0].Value]" --output table

Mỗi sáng morning.ps1 chạy lệnh UPSERT để cập nhật IP mới:

aws route53 change-resource-record-sets --hosted-zone-id Z0999500HD1JE8VHHDN2 `
  --change-batch file://changes.json
# changes.json:
{
  "Changes": [{
    "Action": "UPSERT",
    "ResourceRecordSet": {
      "Name": "vhnlong.store",
      "Type": "A",
      "TTL": 60,
      "ResourceRecords": [{ "Value": "54.179.253.43" }]
    }
  }]
}
⚠️ Vấn đề Phụ thuộc vào việc morning.ps1 chạy thành công. Nếu lỡ EC2 chết giữa ngày, IP không tự cập nhật → user bị 502 đến khi bạn nhận ra và chạy lại.

3. Tại sao cần ALB

ALB giải quyết 4 vấn đề mà setup hiện tại đang gặp:

#Vấn đề hiện tạiALB giải quyết
1EC2 IP đổi mỗi sáng → phải update Route 53ALB DNS cố định mãi mãi → Route 53 ALIAS không bao giờ phải update
2EC2 chết giữa ngày → user bị 502ALB health-check mỗi 30s → tự ngừng route đến EC2 lỗi
3SSL cert tự lấy bằng certbot → renew thủ côngACM cert tự renew miễn phí
4Khó scale lên 2+ EC2Đăng ký nhiều EC2 vào target group → ALB tự balance
ℹ️ Lưu ý cho demo project Bạn chỉ có 1 EC2 + 1 user (chính bạn) → vấn đề 4 không quan trọng. Vấn đề 1-3 vẫn có giá trị thật.

4. ALB cấu tạo bên trong

"ALB" thực ra là tên gọi tắt cho 3 resource AWS hoạt động cùng nhau:

┌─────────────────────────────────────────────────────────────┐ │ 1. LOAD BALANCER (ten + DNS co dinh) │ │ DNS: myapp-alb-1234abcd.ap-southeast-1.elb.amazonaws.com │ │ Subnets: 2+ AZ (yeu cau bat buoc cua AWS) │ └─────────────┬───────────────────────────────────────────────┘ │ │ co 1 hoac nhieu... ▼ ┌─────────────────────────────────────────────────────────────┐ │ 2. LISTENER │ │ HTTP :80 → redirect 443 │ │ HTTPS :443 (kem ACM cert) → forward to target group │ └─────────────┬───────────────────────────────────────────────┘ │ │ forward toi... ▼ ┌─────────────────────────────────────────────────────────────┐ │ 3. TARGET GROUP (nhom backend) │ │ Protocol: HTTP :80 │ │ Health check: GET /api/health expected 200 │ │ Targets: │ │ - i-032d0ab2ebdbf64a5 (EC2 hien tai) -- healthy │ │ - (them EC2 khac neu can) │ └─────────────────────────────────────────────────────────────┘
ResourceTương tựGhi chú

ListenerMỗi cổng gọi vàoMỗi listener = 1 protocol+port (vd HTTPS:443). Có rule routing

5. A record vs ALIAS vs CNAME

Khi muốn vhnlong.store trỏ vào ALB, có 3 cách:

CáchMap sangCó dùng được không?
A recordIP cụ thể❌ Không — ALB không có IP tĩnh, IP thay đổi liên tục
CNAMEtên DNS (vd myalb-1234.elb.amazonaws.com)⚠️ Được cho subdomain, NHƯNG root domain (vhnlong.store không có www) không cho CNAME (DNS RFC cấm)
ALIAS (Route 53 only)AWS resource (ALB, CloudFront, S3...)✅ Đây là cách đúng. Hoạt động cho cả root domain. Miễn phí query. AWS tự xử lý IP đổi
💡 Vì sao có ALIAS? ALIAS là phát minh riêng của AWS để "chữa" cái yếu của CNAME (không dùng được cho root). Với người dùng, nó trả về IP như A record — nhưng Route 53 tự update IP khi ALB thay.

8. Hướng dẫn setup ALB (CLI từng bước)

Phần này là blueprint. Khi bạn nói "bắt đầu bước b", tôi sẽ chạy các lệnh này theo thứ tự, dừng để verify từng bước.

1 Lấy thông tin VPC/Subnets/SG hiện có

ALB cần ít nhất 2 subnet ở 2 AZ khác nhau (AWS yêu cầu cho high availability).

# Lay VPC mac dinh + subnets
aws ec2 describe-vpcs --region ap-southeast-1 `
  --filters "Name=is-default,Values=true" `
  --query "Vpcs[0].VpcId" --output text

aws ec2 describe-subnets --region ap-southeast-1 `
  --filters "Name=vpc-id,Values=<VPC_ID>" `
  --query "Subnets[].[SubnetId,AvailabilityZone]" --output table

2 Tạo Security Group cho ALB (mở port 80, 443 từ internet)

aws ec2 create-security-group --region ap-southeast-1 `
  --group-name myapp-alb-sg `
  --description "ALB inbound 80/443 from internet" `
  --vpc-id <VPC_ID>
# Tra ve SG_ID, vd: sg-0a1b2c3d4e5f6

aws ec2 authorize-security-group-ingress --group-id sg-0a1b2c... `
  --protocol tcp --port 80 --cidr 0.0.0.0/0
aws ec2 authorize-security-group-ingress --group-id sg-0a1b2c... `
  --protocol tcp --port 443 --cidr 0.0.0.0/0
ℹ️ EC2 SG cũng cần điều chỉnh Sau này EC2 chỉ nên cho phép ALB vào (không cho public). Bước này làm sau, không phải bây giờ.

3 Tạo ACM certificate cho HTTPS

ACM cert cho ALB phải cùng region với ALB (ap-southeast-1). Khác với CloudFront — CloudFront yêu cầu us-east-1.

aws acm request-certificate --region ap-southeast-1 `
  --domain-name vhnlong.store `
  --subject-alternative-names www.vhnlong.store `
  --validation-method DNS `
  --query "CertificateArn" --output text
# Tra ve ARN, vd: arn:aws:acm:ap-southeast-1:...:certificate/abc-123

# Lay DNS record can them de validate domain
aws acm describe-certificate --region ap-southeast-1 --certificate-arn <ARN> `
  --query "Certificate.DomainValidationOptions[].ResourceRecord"

Sau đó thêm CNAME validation record vào Route 53 (lệnh sẽ dài, có trong script). Đợi ~2-5 phút, ACM cert chuyển từ PENDING_VALIDATION → ISSUED.

4 Tạo Target Group

aws elbv2 create-target-group --region ap-southeast-1 `
  --name myapp-tg `
  --protocol HTTP `
  --port 80 `
  --vpc-id <VPC_ID> `
  --target-type instance `
  --health-check-protocol HTTP `
  --health-check-path /api/health `
  --health-check-interval-seconds 30 `
  --healthy-threshold-count 2 `
  --unhealthy-threshold-count 2 `
  --query "TargetGroups[0].TargetGroupArn" --output text

5 Tạo ALB

aws elbv2 create-load-balancer --region ap-southeast-1 `
  --name myapp-alb `
  --subnets <SUBNET_ID_AZ1> <SUBNET_ID_AZ2> `
  --security-groups sg-0a1b2c... `
  --scheme internet-facing `
  --type application `
  --query "LoadBalancers[0].{ARN:LoadBalancerArn,DNS:DNSName,Zone:CanonicalHostedZoneId}"

6 Tạo Listener (HTTPS:443 + HTTP:80 redirect)

# HTTPS listener voi ACM cert
aws elbv2 create-listener --region ap-southeast-1 `
  --load-balancer-arn <ALB_ARN> `
  --protocol HTTPS --port 443 `
  --certificates CertificateArn=<ACM_ARN> `
  --default-actions Type=forward,TargetGroupArn=<TG_ARN>

# HTTP listener redirect sang HTTPS
aws elbv2 create-listener --region ap-southeast-1 `
  --load-balancer-arn <ALB_ARN> `
  --protocol HTTP --port 80 `
  --default-actions '{"Type":"redirect","RedirectConfig":{"Protocol":"HTTPS","Port":"443","StatusCode":"HTTP_301"}}'

7 Đăng ký EC2 vào Target Group

aws elbv2 register-targets --region ap-southeast-1 `
  --target-group-arn <TG_ARN> `
  --targets Id=<INSTANCE_ID>

# Doi vai phut roi check health
aws elbv2 describe-target-health --region ap-southeast-1 --target-group-arn <TG_ARN> `
  --query "TargetHealthDescriptions[].{Id:Target.Id,State:TargetHealth.State,Reason:TargetHealth.Reason}"
⚠️ EC2 SG phải cho ALB vào Nếu EC2 SG hiện tại chỉ mở 80 từ 0.0.0.0/0 thì OK. Nhưng nếu muốn close port khỏi internet (best practice), phải mở 80 chỉ từ ALB SG: aws ec2 authorize-security-group-ingress --group-id <EC2_SG> --protocol tcp --port 80 --source-group sg-0a1b2c...

8 Trỏ domain vào ALB (Route 53 ALIAS)

# Lay HostedZoneId cua ALB (KHAC voi hosted zone cua domain!)
# Da co o buoc 5 trong field "CanonicalHostedZoneId"

# Update Route 53 record: A type, AliasTarget
aws route53 change-resource-record-sets --hosted-zone-id Z0999500HD1JE8VHHDN2 `
  --change-batch '{
    "Changes": [{
      "Action": "UPSERT",
      "ResourceRecordSet": {
        "Name": "vhnlong.store",
        "Type": "A",
        "AliasTarget": {
          "HostedZoneId": "<ALB_HOSTED_ZONE_ID>",
          "DNSName": "<ALB_DNS>",
          "EvaluateTargetHealth": true
        }
      }
    }]
  }'
💡 ALIAS không có TTL Route 53 tự quản TTL cho ALIAS (60s mặc định). Không cần truyền.

9. Test & verify

# 1. Health check trong target group co healthy chua?
aws elbv2 describe-target-health --region ap-southeast-1 --target-group-arn <TG_ARN>
# Expect: State = "healthy"

# 2. Truy cap qua ALB DNS truc tiep
curl -vk https://<ALB_DNS>/api/health
# Expect: 200 {"status":"ok"}

# 3. Truy cap qua domain (sau khi DNS propagate ~60s)
curl -vk https://vhnlong.store/api/health
# Expect: 200, va header se co "Server: awselb/2.0"

# 4. Verify cert duoc dung la ACM, khong phai Let's Encrypt
openssl s_client -connect vhnlong.store:443 -servername vhnlong.store < /dev/null | grep -i issuer
# Expect: issuer=Amazon (cu se la Let's Encrypt)

10. Tích hợp vào morning.ps1 / evening.ps1

Sau khi ALB chạy ổn định, sửa scripts:

morning.ps1

  • Bỏ: Route 53 UPSERT IP (vì domain đã trỏ ALIAS vào ALB)
  • Thêm: aws elbv2 register-targets --target-group-arn $TG_ARN --targets Id=$INSTANCE_ID
  • Bỏ: Certbot/SSL setup trên EC2 (vì ACM lo HTTPS)
  • Sửa: Nginx config trên EC2 — chỉ cần listen :80, không cần SSL

evening.ps1

  • Thêm: aws elbv2 deregister-targets ... (không bắt buộc — terminate EC2 thì target tự ra khỏi TG)
  • Không xóa ALB nếu muốn giữ DNS cố định 24/7. Nếu muốn cost $0 đêm → xóa ALB rồi tạo lại sáng (phức tạp hơn — domain phải re-trỏ vào ALB DNS mới)

12. Cleanup khi xong

# Thu tu xoa NGUOC voi luc tao

# 1. Tro domain ve IP cu (UPSERT lai A record A type don gian)
# Khong xoa A record, chi update lai value
.\scripts\morning.ps1  # Se UPSERT lai IP EC2 hien tai

# 2. Xoa Listener (HTTPS + HTTP)
aws elbv2 delete-listener --listener-arn <HTTPS_LISTENER_ARN>
aws elbv2 delete-listener --listener-arn <HTTP_LISTENER_ARN>

# 3. Xoa ALB
aws elbv2 delete-load-balancer --load-balancer-arn <ALB_ARN>
# Doi ~30s de ALB hoan tat shutdown

# 4. Xoa Target Group
aws elbv2 delete-target-group --target-group-arn <TG_ARN>

# 5. Xoa ACM cert (tu chon — co the giu lai dung sau)
aws acm delete-certificate --certificate-arn <ACM_ARN>

# 6. Xoa security group cua ALB
aws ec2 delete-security-group --group-id sg-0a1b2c...
🚨 Đừng xóa Route 53 hosted zone Vẫn cần để domain hoạt động. Hosted zone chỉ tốn $0.50/tháng — nếu xóa rồi tạo lại sẽ phải cập nhật nameserver ở registrar (Namecheap...).

13. Troubleshooting

Target unhealthy: "Health checks failed with these codes: [502]"

  • EC2 chưa mở port 80 cho ALB SG → authorize-security-group-ingress --source-group <ALB_SG>
  • Nginx trên EC2 chưa listen :80 hoặc đường dẫn /api/health không tồn tại
  • Healthcheck timeout quá ngắn — backend khởi động chậm → tăng --health-check-timeout-seconds

ACM cert mãi PENDING_VALIDATION

  • CNAME validation record chưa add vào Route 53 → check: aws acm describe-certificate --query "Certificate.DomainValidationOptions[].ValidationStatus"
  • Domain chưa propagate (DNS check: dig _abc123.vhnlong.store CNAME +short phải trả về _xyz.acm-validations.aws)
  • ACM ở SAI region — cert cho ALB phải ở cùng region ALB

Truy cập vhnlong.store vẫn ra IP cũ (không phải ALB)

  • DNS cache cũ trên client → flush: ipconfig /flushdns (Windows) / browser hard reload
  • Route 53 record vẫn là A → IP. Đổi sang A → ALIAS
  • TTL cao → đợi (TTL cũ 60s nên nhanh)

HTTPS qua ALB nhưng cert lỗi (NET::ERR_CERT_COMMON_NAME_INVALID)

  • ACM cert chưa cover www.vhnlong.store → request lại với SAN
  • Listener gắn nhầm cert

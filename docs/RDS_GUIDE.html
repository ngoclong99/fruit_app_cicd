1. Chuyển từ Docker PostgreSQL → RDS

RDS (Relational Database Service) là dịch vụ quản lý database của AWS — không phải tự quản lý server, backup, patching. Trade-off: tốn tiền hơn Docker chạy trên EC2.

💡 Khi nào nên dùng RDS?
  • Production thật — không muốn lo backup, restore, patching
  • Multi-AZ failover — DB tự switch sang zone khác khi 1 zone chết
  • Học pattern managed service
Cho demo/học: Docker DB rẻ hơn ~80%. Tạo RDS chỉ khi học, delete ngay sau khi xong.

2

Tạo database và user trong RDS

SSH vào EC2 (vì RDS không public access, chỉ EC2 cùng VPC mới connect được), rồi kết nối RDS bằng master user:

psql -h <rds-endpoint> -U postgres -d postgres

Khi vào psql prompt, chạy SQL sau:

CREATE USER "userPostgres" WITH PASSWORD '<DB_PASSWORD_trong_SSM>';
CREATE DATABASE todos_db;
GRANT ALL PRIVILEGES ON DATABASE todos_db TO "userPostgres";
\c todos_db
GRANT CREATE ON SCHEMA public TO "userPostgres";
GRANT USAGE ON SCHEMA public TO "userPostgres";

-- Tao bang thu cong (userPostgres khong co quyen CREATE TABLE tren RDS PG15)
CREATE TABLE IF NOT EXISTS todos (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL,
  done BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
GRANT ALL ON TABLE todos TO "userPostgres";
GRANT ALL ON SEQUENCE todos_id_seq TO "userPostgres";
\q
🔑 Tại sao phải tạo bảng bằng master user? PostgreSQL 15 mặc định KHÔNG cho non-superuser tạo bảng trong schema public. Đây là thay đổi bảo mật từ PG15 — khác với PG14 trở xuống.
3

Cập nhật SSM Parameter Store

App đọc DB credentials từ SSM khi deploy — cập nhật trỏ về RDS endpoint:

aws ssm put-parameter --name "/myapp/production/DB_HOST" --value "<rds-endpoint>" --type String --overwrite --region ap-southeast-1
aws ssm put-parameter --name "/myapp/production/DB_USER" --value "userPostgres" --type String --overwrite --region ap-southeast-1
aws ssm put-parameter --name "/myapp/production/DB_PASSWORD" --value "<password>" --type SecureString --overwrite --region ap-southeast-1
aws ssm put-parameter --name "/myapp/production/DB_NAME" --value "todos_db" --type String --overwrite --region ap-southeast-1
⚠️ DB_PASSWORD type = SecureString Password BẮT BUỘC SecureString (mã hoá KMS), không phải String. Các param khác có thể String.
4

Cập nhật docker-compose.prod.yml

Vì DB giờ chạy trên RDS, không cần Docker container db nữa:

  • Xoá service db và volume postgres_data
  • Xoá depends_on: db trong service backend và pgadmin
  • DB_HOST sẽ tự đọc từ SSM (env injected bởi deploy workflow)
✅ Backend tự bật SSL khi connect RDS backend/src/db.ts đã check DB_HOST.includes('rds.amazonaws.com') → tự enable SSL. Không cần config thêm gì.
5

Deploy

Push code lên main → GitHub Actions tự deploy với env mới. App sẽ kết nối RDS thay vì container DB.

git add docker-compose.prod.yml
git commit -m "chore: migrate to RDS"
git push origin main

Sau ~3-5 phút workflow xong, verify:

ssh ubuntu@<EC2-IP>
docker logs myapp-production-backend-1 --tail 30
# Phải thấy log connect RDS thành công, không có lỗi "ECONNREFUSED"

db là service name trong docker-compose, Docker network DNS sẽ tự resolve.

3

Push code → deploy

🚨 Đừng quên xoá RDS! RDS chạy 24/7 = ~$15/tháng cho db.t3.micro + storage. Tạo ra mà không xoá là leak chi phí lớn nhất.

3. Xử lý lỗi thường gặp

no pg_hba.conf entry ... no encryption

Nguyên nhân: Backend kết nối không SSL, RDS yêu cầu SSL.

Fix: backend/src/db.ts đã có SSL auto-detect khi DB_HOST chứa rds.amazonaws.com. Đảm bảo code mới nhất được deploy:

ssh ubuntu@<EC2-IP> "docker exec myapp-production-backend-1 cat /app/dist/db.js | grep ssl"
# Phải thấy: ssl: dbHost.includes('rds.amazonaws.com') ? { rejectUnauthorized: false } : undefined

password authentication failed for user "userPostgres"

Nguyên nhân: Password trong SSM không khớp với password đặt trong RDS.

Fix:

# Lay password tu SSM
aws ssm get-parameter --name "/myapp/production/DB_PASSWORD" --with-decryption --query "Parameter.Value" --output text --region ap-southeast-1

# Reset password trong RDS
psql -h <rds-endpoint> -U postgres -d postgres
ALTER USER "userPostgres" WITH PASSWORD '<password_trong_ssm>';
\q

permission denied for schema public (code 42501)

Nguyên nhân: RDS PostgreSQL 15 mặc định không cho user tạo bảng trong schema public (security change from PG14 → PG15).

Fix: Tạo bảng bằng master user postgres, sau đó grant:

-- Connect as postgres to todos_db
CREATE TABLE IF NOT EXISTS todos (...);
GRANT ALL ON TABLE todos TO "userPostgres";
GRANT ALL ON SEQUENCE todos_id_seq TO "userPostgres";

Và trong backend/src/db.ts, hàm initDB() chỉ chạy SELECT 1 (không tự tạo bảng).

You can't specify MasterUserPassword for an instance with ManageMasterUserPassword enabled

Nguyên nhân: RDS đang dùng Secrets Manager quản lý password, không thể đổi bằng CLI.

Fix: Lấy password từ Secrets Manager:

aws secretsmanager get-secret-value --secret-id "<arn>" --query "SecretString" --output text --region ap-southeast-1

Nginx dùng port ngẫu nhiên thay vì port 80

Nguyên nhân: source backend/.env bị lỗi do password có ký tự đặc biệt → NGINX_HTTP_PORT không được export.

Fix: deploy.yml phải quote giá trị trong .env:

awk -F'\t' '{n=split($1,a,"/"); print a[n]"='"'"'"$2"'"'"'"}' > backend/.env

pgAdmin mất kết nối sau khi xóa Docker DB

Nguyên nhân: pgAdmin đang connect vào service db đã bị xóa.

Fix: Add new server trong pgAdmin, kết nối trực tiếp vào RDS endpoint với username userPostgres.

db.t3.micro on-demand~$0.021/giờFree tier 12 tháng đầu cho account mới
Storage gp2 20GB~$2.76/thángTính theo dung lượng đăng ký, không phải dùng

✅ Khuyến nghị cho demo Tạo RDS khi cần học, delete ngay sau khi xong. Mỗi buổi học ~$0.04 — không đáng kể nếu nhớ delete.
🚨 Bẫy chi phí thường gặp
  • Storage tính theo đăng ký: Đăng ký 20GB nhưng dùng 1GB vẫn tốn full $2.76
  • Snapshot không tự xoá: Khi delete RDS, AWS hỏi "Create final snapshot?" — nếu chọn Yes mà không xoá snapshot sau đó → vẫn tốn ~$0.095/GB/tháng
  • Multi-AZ: Nếu bật Multi-AZ chi phí gấp đôi
  • Reserved Instance: Demo KHÔNG dùng — chỉ tiết kiệm khi commit 1 năm

Cách xoá RDS hoàn toàn

# 1. Disable deletion protection nếu có
aws rds modify-db-instance --db-instance-identifier <name> --no-deletion-protection --apply-immediately --region ap-southeast-1

# 2. Delete với --skip-final-snapshot (tránh tốn tiền snapshot)
aws rds delete-db-instance --db-instance-identifier <name> --skip-final-snapshot --region ap-southeast-1

# 3. Verify - đợi vài phút, status phải biến mất
aws rds describe-db-instances --region ap-southeast-1

# 4. Xoá manual snapshots còn sót lại (nếu có từ trước)
aws rds describe-db-snapshots --snapshot-type manual --region ap-southeast-1
aws rds delete-db-snapshot --db-snapshot-identifier <snapshot-id> --region ap-southeast-1

1. Tại sao Infrastructure as Code (IaC)

Vấn đề "ClickOps"

  • Sau Phase 3-4, bạn đã click hàng trăm option trên AWS Console
  • Nếu vô tình xóa nhầm → không thể "redo Ctrl+Z" → phải nhớ và làm lại từ đầu

State quan trọng như thế nào

Terraform không hỏi AWS mỗi lần — nó đọc .tfstate để biết đã tạo gì. State chứa cả secret (DB password, private key...) → không commit vào Git và phải backup.

🚨 .tfstate phải remote + lock Local .tfstate chỉ OK cho cá nhân. Team → bắt buộc S3 backend + DynamoDB lock (Module A bên dưới). Mất state = không thể manage infra nữa, phải import lại.

6. Module A — Remote State (S3 + DynamoDB)

📌 Bài học cần biết trước khi bắt đầu
  • Chicken-and-egg problem: Terraform cần backend (S3 bucket) để lưu state, nhưng chưa có gì cả → bootstrap bằng AWS CLI 1 lần
  • State quan trọng hơn code: mất state = không thể manage infra. Phải versioning + backup nghiêm túc
  • State có chứa secret: DB password, private key... → encryption MANDATORY (S3 server-side + KMS)
  • Lock concurrent apply: 2 người apply cùng lúc → race condition, corrupt state. DynamoDB table làm distributed lock
  • Không commit .tfstate vào Git: .gitignore phải có dòng *.tfstate, .terraform/

Cấu trúc backend

ComponentMục đíchTại sao chọn AWS service này
S3 bucketLưu file terraform.tfstate (JSON ~vài KB-MB)11 9's durability, versioning, encryption native
DynamoDB tableDistributed lock — chặn 2 user apply cùng lúcStrong consistency, conditional writes (atomic lock)
KMS key (optional)Encrypt state với customer-managed keyAudit access log per user (vs AES256 mặc định)

A1 Bootstrap — tạo S3 bucket cho state

AWS Console UIAWS CLI

UI walkthrough

  1. Console → S3 → Create bucket
  2. Bucket name: vhnlong-tf-state (phải globally unique — thêm prefix nếu trùng)
  3. AWS Region: Asia Pacific (Singapore) ap-southeast-1
  4. Object Ownership: ACLs disabled (recommended)
  5. Block Public Access settings: Block all public access (tick all 4)
  6. Bucket Versioning: Enable (RẤT QUAN TRỌNG — để revert state khi corrupt)
  7. Default encryption: Server-side encryption with Amazon S3 managed keys (SSE-S3) hoặc KMS
  8. Advanced settings: tick Object Lock nếu cần compliance (tốn thêm bước, optional)
  9. Create bucket

CLI

# 1. Tao bucket
aws s3api create-bucket --region ap-southeast-1 `
  --bucket vhnlong-tf-state `
  --create-bucket-configuration LocationConstraint=ap-southeast-1

# 2. Versioning -- de revert khi state corrupt
aws s3api put-bucket-versioning --bucket vhnlong-tf-state `
  --versioning-configuration Status=Enabled

# 3. Encryption (AES256 mac dinh, hoac dung KMS)
aws s3api put-bucket-encryption --bucket vhnlong-tf-state --server-side-encryption-configuration '{
  "Rules": [{"ApplyServerSideEncryptionByDefault": {"SSEAlgorithm": "AES256"}}]
}'

# 4. Block public access (an toan vi state co secret)
aws s3api put-public-access-block --bucket vhnlong-tf-state `
  --public-access-block-configuration "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"

# 5. Lifecycle rule -- xoa version cu sau 90 ngay (giam cost neu update state nhieu)
$lifecycle = '{
  "Rules": [{
    "ID": "delete-old-versions",
    "Status": "Enabled",
    "Filter": {},
    "NoncurrentVersionExpiration": {"NoncurrentDays": 90}
  }]
}'
$tmpFile = [System.IO.Path]::GetTempFileName()
[System.IO.File]::WriteAllText($tmpFile, $lifecycle)
aws s3api put-bucket-lifecycle-configuration --bucket vhnlong-tf-state --lifecycle-configuration "file://$tmpFile"
Remove-Item $tmpFile -Force

A2 Bootstrap — tạo DynamoDB lock table

AWS Console UIAWS CLI

UI

  1. Console → DynamoDB → Create table
  2. Table name: vhnlong-tf-lock
  3. Partition key: LockID, type String
  4. Sort key: (không có)
  5. Settings: Customize settings
  6. Capacity mode: On-demand (PAY_PER_REQUEST — apply chỉ vài lần/ngày)
  7. Create table

CLI

aws dynamodb create-table --region ap-southeast-1 `
  --table-name vhnlong-tf-lock `
  --attribute-definitions AttributeName=LockID,AttributeType=S `
  --key-schema AttributeName=LockID,KeyType=HASH `
  --billing-mode PAY_PER_REQUEST

# Doi table ACTIVE
aws dynamodb wait table-exists --region ap-southeast-1 --table-name vhnlong-tf-lock
ℹ️ Tại sao tên partition key phải là LockID Terraform's S3 backend code hardcoded tên này. Nếu đặt tên khác → init sẽ fail. Đây là contract của Terraform.

A3 Khai báo backend trong code Terraform

Sửa terraform/main.tf:

terraform {
  required_version = ">= 1.5"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }

  # Backend S3 + DynamoDB lock
  backend "s3" {
    bucket         = "vhnlong-tf-state"           # tu A1
    key            = "production/terraform.tfstate" # path trong bucket -- per env
    region         = "ap-southeast-1"
    encrypt        = true                          # encrypt at rest (su dung S3 encryption)
    dynamodb_table = "vhnlong-tf-lock"             # tu A2
  }
}

provider "aws" {
  region = "ap-southeast-1"
}
⚠️ Backend không support variables Trong block backend "s3" { ... } KHÔNG được dùng var.xxx. Phải hardcode value. Nếu cần multi-env config khác nhau → dùng terraform init -backend-config="bucket=..." -backend-config="key=..." hoặc file backend.hcl.

🗑️ Cleanup Module A — Xóa backend

🚨 Trước khi xóa backend, PHẢI destroy hết infra Terraform managed Nếu xóa backend khi vẫn còn infra managed → bạn không bao giờ destroy được qua Terraform. Phải xóa từng resource manual qua Console (rất khó). 
# ────────── BUOC 1: Destroy het Terraform-managed infra ──────────
cd terraform/
terraform destroy
# Yes/no -- yes

# ────────── BUOC 2: Xoa toan bo object trong bucket (ke ca version cu) ──────────
# Versioning bat thi delete bucket khong xoa duoc neu con version
aws s3api delete-objects --bucket vhnlong-tf-state --delete "{
  \"Objects\": [$(aws s3api list-object-versions --bucket vhnlong-tf-state --output json | jq -r '.Versions[]?, .DeleteMarkers[]? | \"{\\\"Key\\\":\\\"\" + .Key + \"\\\",\\\"VersionId\\\":\\\"\" + .VersionId + \"\\\"}\"' | paste -sd, -)]
}"

# Cach don gian hon (PowerShell):
$versions = aws s3api list-object-versions --bucket vhnlong-tf-state --output json | ConvertFrom-Json
foreach ($v in $versions.Versions) {
  aws s3api delete-object --bucket vhnlong-tf-state --key $v.Key --version-id $v.VersionId
}
foreach ($m in $versions.DeleteMarkers) {
  aws s3api delete-object --bucket vhnlong-tf-state --key $m.Key --version-id $m.VersionId
}

# ────────── BUOC 3: Xoa S3 bucket ──────────
aws s3api delete-bucket --bucket vhnlong-tf-state --region ap-southeast-1

# ────────── BUOC 4: Xoa DynamoDB lock table ──────────
aws dynamodb delete-table --table-name vhnlong-tf-lock --region ap-southeast-1
aws dynamodb wait table-not-exists --table-name vhnlong-tf-lock --region ap-southeast-1

Write-Host "Backend cleanup hoan tat" -ForegroundColor Green

Verify

aws s3api head-bucket --bucket vhnlong-tf-state 2>&1
# Expect: NoSuchBucket

aws dynamodb describe-table --table-name vhnlong-tf-lock --region ap-southeast-1 2>&1
# Expect: ResourceNotFoundException

resource "aws_security_group" "alb" {
  name        = "${var.name}-sg"
  description = "ALB inbound 80/443"
  vpc_id      = var.vpc_id

  ingress {
    protocol    = "tcp"
    from_port   = 80
    to_port     = 80
    cidr_blocks = ["0.0.0.0/0"]
  }
  ingress {
    protocol    = "tcp"
    from_port   = 443
    to_port     = 443
    cidr_blocks = ["0.0.0.0/0"]
  }
  egress {
    protocol    = "-1"
    from_port   = 0
    to_port     = 0
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = var.tags
}

resource "aws_lb" "main" {
  name               = var.name
  load_balancer_type = "application"
  subnets            = var.subnet_ids
  security_groups    = [aws_security_group.alb.id]

  tags = var.tags
}

resource "aws_lb_target_group" "main" {
  name        = "${var.name}-tg"
  port        = 80
  protocol    = "HTTP"
  vpc_id      = var.vpc_id

  # target_type quan trong:
  #   "instance" -- EC2 hoac ASG (Phase 3). ALB route bang instance-id.
  #   "ip"       -- Fargate (Phase 4) hoac IP truc tiep. Fargate task moi co IP rieng trong VPC.
  #   "lambda"   -- Lambda function (use case it gap).
  # Module nay default "ip" vi assumeplaying voi Fargate. Doi sang "instance" neu dung ASG.
  target_type = "ip"

  health_check {
    path                = "/api/health"
    interval            = 30
    healthy_threshold   = 2
    unhealthy_threshold = 2
  }
}

resource "aws_lb_listener" "https" {
  load_balancer_arn = aws_lb.main.arn
  port              = 443
  protocol          = "HTTPS"
  certificate_arn   = var.certificate_arn

  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.main.arn
  }
}

resource "aws_lb_listener" "http" {
  load_balancer_arn = aws_lb.main.arn
  port              = 80
  protocol          = "HTTP"

  default_action {
    type = "redirect"
    redirect {
      port        = "443"
      protocol    = "HTTPS"
      status_code = "HTTP_301"
    }
  }
}

11. Module F — Terraform trong CI/CD

Strategy

  • Pull request: chạy terraform plan, comment plan output vào PR
  • Merge to main: chạy terraform apply tự động
  • Manual gate: GitHub Environment approval cho production

GitHub Actions workflow ví dụ

# .github/workflows/terraform.yml
name: Terraform

on:
  pull_request:
    paths: ['terraform/**']
  push:
    branches: [main]
    paths: ['terraform/**']

jobs:
  plan:
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: hashicorp/setup-terraform@v3

      - name: Configure AWS
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region:            ap-southeast-1

      - run: terraform init
        working-directory: terraform
      - run: terraform plan -out=tfplan
        working-directory: terraform

      - name: Comment plan to PR
        uses: actions/github-script@v7
        with:
          script: |
            const plan = require('child_process').execSync('terraform show tfplan').toString();
            github.rest.issues.createComment({
              ...context.repo,
              issue_number: context.issue.number,
              body: '```\n' + plan + '\n```'
            });

  apply:
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: production   # yeu cau manual approval
    steps:
      - uses: actions/checkout@v4
      - uses: hashicorp/setup-terraform@v3
      - uses: aws-actions/configure-aws-credentials@v4
        with: { ... }
      - run: terraform init
      - run: terraform apply -auto-approve

15. Troubleshooting

"Error acquiring state lock"

  • 1 lần apply trước đó bị crash → lock bị treo
  • Force unlock: terraform force-unlock <lock-id> (chỉ khi chắc không ai đang chạy)

Plan ra "changes" dù không sửa code

  • Ai đó sửa resource trên Console → drift. Cách xử lý: hoặc revert trên Console, hoặc import lại + update code cho khớp
  • Provider version đổi → API behavior khác

Import resource nhưng vẫn báo "will be created"

  • Resource address sai → check terraform state list
  • Một số attribute không match (tag, name) → fill cho đúng

State bị mất

  • S3 versioning đang bật → restore version cũ qua console
  • Không có backup → phải import lại tất cả resource (đau)

Apply trên CI nhưng credentials không đủ

  • IAM user github-actions-deploy cần quyền tạo/xóa mọi resource bạn quản lý → có thể add PowerUserAccess (rộng) hoặc viết policy hẹp

1. Tại sao Infrastructure as Code (IaC)

Vấn đề "ClickOps"

  • Sau Phase 3-4, bạn đã click hàng trăm option trên AWS Console
  • Nếu vô tình xóa nhầm → không thể "redo Ctrl+Z" → phải nhớ và làm lại từ đầu
  • Muốn tạo môi trường staging giống production → phải click lại 100% như cũ
  • Đồng nghiệp join project → không biết hạ tầng có những gì
  • Disaster recovery → không có nguồn để khôi phục

IaC là gì

Mô tả hạ tầng bằng code, version trong Git, apply tự động.

4. First Terraform — hello world

1 Tạo thư mục

mkdir e:\AWS\Deploy-1\terraform
cd e:\AWS\Deploy-1\terraform

2 File main.tf đầu tiên

# Khai bao provider (AWS, version, region)
terraform {
  required_version = ">= 1.5"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "ap-southeast-1"
}

# Resource dau tien -- tao 1 S3 bucket de test
resource "aws_s3_bucket" "hello" {
  bucket = "vhnlong-tf-hello-2026"  # phai unique toan cau
}

# Output -- in ra sau khi apply
output "bucket_arn" {
  value = aws_s3_bucket.hello.arn
}

3 4 lệnh Terraform cốt lõi

# 1. Init -- tai provider plugin (lan dau)
terraform init
# Tao thu muc .terraform/ va file .terraform.lock.hcl

# 2. Plan -- xem se thay doi gi (KHONG ap dung)
terraform plan
# Output: + aws_s3_bucket.hello will be created

# 3. Apply -- ap dung
terraform apply
# Hoi yes/no, go 'yes' de tao bucket that
# Output: bucket_arn = arn:aws:s3:::vhnlong-tf-hello-2026

# 4. Destroy -- xoa moi thu da tao
terraform destroy
💡 Workflow chuẩn edit .tf → terraform plan → review → terraform apply → git commit. Plan trước, đọc kỹ trước khi apply.

State quan trọng như thế nào

Terraform không hỏi AWS mỗi lần — nó đọc .tfstate để biết đã tạo gì. State chứa cả secret (DB password, private key...) → không commit vào Git và phải backup.

🚨 .tfstate phải remote + lock Local .tfstate chỉ OK cho cá nhân. Team → bắt buộc S3 backend + DynamoDB lock (Module A bên dưới). Mất state = không thể manage infra nữa, phải import lại.

6. Module A — Remote State (S3 + DynamoDB)

Cấu trúc

  • S3 bucket: lưu file terraform.tfstate
  • DynamoDB table: lock để 2 người không apply cùng lúc

A1 Bootstrap (tạo backend bằng tay)

Vấn đề "chicken-and-egg": muốn dùng S3 làm backend nhưng S3 chưa có. Có 2 cách:

  • Tạo S3 + DynamoDB bằng CLI (1 lần)
  • Tạo bằng Terraform với local state, rồi migrate state lên S3 (đẹp hơn)

Đề xuất cách 1 cho đơn giản:

# Tao bucket cho state
aws s3api create-bucket `
  --bucket vhnlong-tf-state `
  --region ap-southeast-1 `
  --create-bucket-configuration LocationConstraint=ap-southeast-1

# Bat versioning de revert state khi can
aws s3api put-bucket-versioning `
  --bucket vhnlong-tf-state `
  --versioning-configuration Status=Enabled

# Encrypt at rest
aws s3api put-bucket-encryption `
  --bucket vhnlong-tf-state `
  --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'

# Block public access
aws s3api put-public-access-block `
  --bucket vhnlong-tf-state `
  --public-access-block-configuration "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"

# Tao DynamoDB table cho lock
aws dynamodb create-table `
  --region ap-southeast-1 `
  --table-name vhnlong-tf-lock `
  --attribute-definitions AttributeName=LockID,AttributeType=S `
  --key-schema AttributeName=LockID,KeyType=HASH `
  --billing-mode PAY_PER_REQUEST

A2 Khai báo backend trong code

Sửa main.tf:

terraform {
  required_version = ">= 1.5"
  required_providers { ... }

  backend "s3" {
    bucket         = "vhnlong-tf-state"
    key            = "production/terraform.tfstate"  # path trong bucket
    region         = "ap-southeast-1"
    encrypt        = true
    dynamodb_table = "vhnlong-tf-lock"
  }
}

A3 Migrate state local → S3

terraform init -migrate-state
# Hoi yes/no -- yes de copy state cu len S3 backend

# Verify -- xoa state local di, plan van OK
Remove-Item terraform.tfstate*
terraform plan  # van doc state tu S3
ℹ️ Chi phí backend S3: vài KB → $0.0001/tháng. DynamoDB pay-per-request: vài cents nếu apply nhiều. ~$0/tháng cho demo.

7. Module B — Import existing AWS resources

Bạn đã có ALB, ASG, ECS, S3... từ Phase 3-4. Không cần xóa rồi tạo lại — import chúng vào Terraform state.

B1 Cách 1 — Lệnh terraform import

Format: terraform import <resource_address> <cloud_id>

# 1. Viet skeleton resource trong .tf (chua co value)
# resources.tf:
resource "aws_lb" "main" {
  # de trong, se fill sau khi import
}

# 2. Lay ARN cua ALB hien tai
aws elbv2 describe-load-balancers --names myapp-alb `
  --query "LoadBalancers[0].LoadBalancerArn" --output text

# 3. Import
terraform import aws_lb.main <ALB_ARN>

# 4. terraform plan -- se bao "no changes" hoac liet ke field bi khac
# Fill cac field thieu trong .tf cho khop voi reality

B2 Cách 2 — import block (Terraform 1.5+, dễ hơn)

# resources.tf:
import {
  to = aws_lb.main
  id = "arn:aws:elasticloadbalancing:ap-southeast-1:529568113348:loadbalancer/app/myapp-alb/abc123"
}

resource "aws_lb" "main" {
  name = "myapp-alb"
  # ... fill sau
}

# Generate config tu existing
terraform plan -generate-config-out=generated.tf
# Terraform sinh ra file generated.tf voi day du field. Merge thu cong vao .tf cua ban.

8. Module C — Refactor thành modules

Tại sao

1 file main.tf 1000 dòng = không maintain được. Tách thành modules theo concern:

terraform/ ├── main.tf # root: provider + backend + module calls ├── variables.tf # input vars ├── outputs.tf # output (ALB DNS, RDS endpoint...) ├── terraform.tfvars # values cua vars (gitignore neu co secret) ├── modules/ │ ├── network/ │ │ ├── main.tf # VPC, subnets, security groups │ │ ├── variables.tf │ │ └── outputs.tf │ ├── alb/ │ │ ├── main.tf # ALB + listeners + target groups │ │ ├── variables.tf │ │ └── outputs.tf │ ├── ecs/ │ │ ├── main.tf # cluster + service + task def │ │ ├── variables.tf │ │ └── outputs.tf │ ├── rds/ │ │ ├── main.tf # RDS instance + subnet group │ │ ├── variables.tf │ │ └── outputs.tf │ └── s3-cdn/ │ ├── main.tf # bucket + CloudFront + OAC │ ├── variables.tf │ └── outputs.tf └── environments/ ├── production/ │ ├── main.tf # goi modules voi var production │ └── terraform.tfvars └── staging/ ├── main.tf └── terraform.tfvars

C1 Ví dụ module ALB

modules/alb/variables.tf:

variable "name"            { type = string }
variable "vpc_id"          { type = string }
variable "subnet_ids"      { type = list(string) }
variable "certificate_arn" { type = string }
variable "tags" {
  type    = map(string)
  default = {}
}

modules/alb/main.tf:

resource "aws_security_group" "alb" {
  name        = "${var.name}-sg"
  description = "ALB inbound 80/443"
  vpc_id      = var.vpc_id

  ingress {
    protocol    = "tcp"
    from_port   = 80
    to_port     = 80
    cidr_blocks = ["0.0.0.0/0"]
  }
  ingress {
    protocol    = "tcp"
    from_port   = 443
    to_port     = 443
    cidr_blocks = ["0.0.0.0/0"]
  }
  egress {
    protocol    = "-1"
    from_port   = 0
    to_port     = 0
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = var.tags
}

resource "aws_lb" "main" {
  name               = var.name
  load_balancer_type = "application"
  subnets            = var.subnet_ids
  security_groups    = [aws_security_group.alb.id]

  tags = var.tags
}

resource "aws_lb_target_group" "main" {
  name        = "${var.name}-tg"
  port        = 80
  protocol    = "HTTP"
  vpc_id      = var.vpc_id
  target_type = "ip"  # Fargate dung IP target

  health_check {
    path                = "/api/health"
    interval            = 30
    healthy_threshold   = 2
    unhealthy_threshold = 2
  }
}

resource "aws_lb_listener" "https" {
  load_balancer_arn = aws_lb.main.arn
  port              = 443
  protocol          = "HTTPS"
  certificate_arn   = var.certificate_arn

  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.main.arn
  }
}

resource "aws_lb_listener" "http" {
  load_balancer_arn = aws_lb.main.arn
  port              = 80
  protocol          = "HTTP"

  default_action {
    type = "redirect"
    redirect {
      port        = "443"
      protocol    = "HTTPS"
      status_code = "HTTP_301"
    }
  }
}

modules/alb/outputs.tf:

output "alb_dns_name"      { value = aws_lb.main.dns_name }

11. Module F — Terraform trong CI/CD

Strategy

  • Pull request: chạy terraform plan, comment plan output vào PR
  • Merge to main: chạy terraform apply tự động
  • Manual gate: GitHub Environment approval cho production

GitHub Actions workflow ví dụ

# .github/workflows/terraform.yml
name: Terraform

on:
  pull_request:
    paths: ['terraform/**']
  push:
    branches: [main]
    paths: ['terraform/**']

jobs:
  plan:
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: hashicorp/setup-terraform@v3

      - name: Configure AWS
        uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region:            ap-southeast-1

      - run: terraform init
        working-directory: terraform
      - run: terraform plan -out=tfplan
        working-directory: terraform

      - name: Comment plan to PR
        uses: actions/github-script@v7
        with:
          script: |
            const plan = require('child_process').execSync('terraform show tfplan').toString();
            github.rest.issues.createComment({
              ...context.repo,
              issue_number: context.issue.number,
              body: '```\n' + plan + '\n```'
            });

  apply:
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    environment: production   # yeu cau manual approval
    steps:
      - uses: actions/checkout@v4
      - uses: hashicorp/setup-terraform@v3
      - uses: aws-actions/configure-aws-credentials@v4
        with: { ... }
      - run: terraform init
      - run: terraform apply -auto-approve

13. Lệnh hay dùng

# Format code
terraform fmt -recursive

# Validate syntax (khong goi AWS)
terraform validate

# Plan với detailed exit code -- 0=no change, 1=error, 2=changes
terraform plan -detailed-exitcode

# Apply chỉ 1 resource
terraform apply -target=aws_lb.main

# Refresh state -- so sanh state file voi reality o AWS
terraform refresh

# Xem state
terraform state list
terraform state show aws_lb.main
terraform state pull > backup.tfstate

# Sua state khi sai (cẩn thận)
terraform state rm aws_lb.main          # xoa khoi state -- KHONG xoa AWS
terraform state mv aws_lb.main aws_lb.new  # rename

# Force unlock neu lock bi treo (vi du Ctrl+C giua chung)
terraform force-unlock <lock-id>

# Output
terraform output                # tat ca
terraform output -json          # cho script
terraform output alb_dns_name   # 1 cai

14. Cleanup an toàn

# 1. Destroy moi thing trong .tf hien tai
terraform destroy

# 2. Xoa state file local (neu chua migrate)
Remove-Item terraform.tfstate*

# 3. Xoa S3 backend bucket (lan cuoi cung)
aws s3 rm s3://vhnlong-tf-state --recursive
aws s3api delete-bucket --bucket vhnlong-tf-state --region ap-southeast-1

# 4. Xoa DynamoDB lock table
aws dynamodb delete-table --table-name vhnlong-tf-lock --region ap-southeast-1
🚨 Trước khi destroy terraform plan -destroy in xem se xoa gi. Đọc kỹ. Xác nhận đúng môi trường (workspace / directory). Đã có ai dùng database không? Đã backup chưa?

15. Troubleshooting

"Error acquiring state lock"

  • 1 lần apply trước đó bị crash → lock bị treo
  • Force unlock: terraform force-unlock <lock-id> (chỉ khi chắc không ai đang chạy)

Plan ra "changes" dù không sửa code

  • Ai đó sửa resource trên Console → drift. Cách xử lý: hoặc revert trên Console, hoặc import lại + update code cho khớp
  • Provider version đổi → API behavior khác

Import resource nhưng vẫn báo "will be created"

  • Resource address sai → check terraform state list
  • Một số attribute không match (tag, name) → fill cho đúng

State bị mất

  • S3 versioning đang bật → restore version cũ qua console
  • Không có backup → phải import lại tất cả resource (đau)

Apply trên CI nhưng credentials không đủ

  • IAM user github-actions-deploy cần quyền tạo/xóa mọi resource bạn quản lý → có thể add PowerUserAccess (rộng) hoặc viết policy hẹp

1. Khác biệt với phiên bản EC2/nginx — khi nào nên dùng?

Phiên bản gốc (huong-dan-docker-aws-cicd) đặt cả frontend và backend trên cùng 1 EC2, dùng nginx làm reverse proxy phục vụ cả 2. Phiên bản này tách frontend ra S3 + CloudFront để có 3 lợi ích quan trọng:

Tiêu chíEC2/nginx (cũ)S3+CloudFront (mới)
FE accessible khi EC2 down❌ Không — FE cùng số phận với BE✅ 24/7 — S3+CF luôn live
CDN cache global❌ Mỗi request về VN-Singapore✅ CloudFront edge cache toàn cầu
Chi phí FE storage/serving~$0.02/hr EBS + bandwidth EC2~$0/tháng (free tier 1TB)
Build time CI/CD~5 phút (npm build + docker build + ECR push)~2 phút (npm build + s3 sync)
Độ phức tạp setup AWSĐơn giản (1 EC2)Phức tạp hơn — thêm S3, ACM, CloudFront, OAC
Khi nào dùngDemo/internal đơn giảnProduction thật / cần FE uptime cao / học CloudFront
✅ Khi nào nên chọn phiên bản này? Bạn muốn FE luôn live (kể cả khi BE bị tạm tắt để tiết kiệm chi phí học), muốn học CloudFront/S3/ACM, hoặc deploy production thật cho người dùng.
⚠️ Khi nào nên tránh? Project demo cực kỳ đơn giản, deploy 1 lần để show, không cần uptime cao → version cũ đơn giản hơn, ít moving parts hơn.

Yêu cầu kỹ thuật bổ sung so với version cũ

  • Domain riêng (vd: example.com) — bắt buộc, không thể chỉ dùng IP EC2 vì CloudFront cần ACM cert
  • Hosted zone Route 53 cho domain đó
  • JWT Bearer token auth (không phải cookie-based) — đơn giản CORS hơn nhiều
  • Vite/React hoặc build tool nào hash filenames (immutable assets) — giúp CloudFront cache hiệu quả

2.2 Tại sao chia ra 2 subdomain?

Lý doGiải thích
BE không bị CloudFront cacheNếu BE dùng same domain với CloudFront, mỗi API request đi qua CloudFront → tốn 50-100ms + có thể bị cache nhầm
Debug dễ hơncurl https://api.example.com đi thẳng EC2 — nếu lỗi biết ngay BE hay CloudFront
FE độc lập lifecycleBE EC2 tắt → FE vẫn truy cập được. User thấy trang chủ + có thông báo "API maintenance"
Có thể scale BE riêngSau này muốn add ALB cho BE (multi-AZ) không ảnh hưởng FE
🔑 Same-origin vs CORS Vì FE ở example.com và BE ở api.example.com là khác origin → browser sẽ enforce CORS. BE phải explicitly set Access-Control-Allow-Origin: https://example.com. Xem chi tiết ở Section 9.

4.2 Backend Dockerfile

Multi-stage build: stage 1 compile TypeScript, stage 2 chỉ chứa runtime. Tương tự version EC2/nginx nhưng không cần đổi gì khi migrate sang S3+CloudFront.

# ═══ STAGE 1: Build ═══
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# ═══ STAGE 2: Production ═══
FROM node:20-alpine
RUN apk add --no-cache curl dumb-init
RUN addgroup -g 1001 nodejs && adduser -S -u 1001 -G nodejs nodejs
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev && npm cache clean --force
COPY --from=builder --chown=nodejs:nodejs /app/dist ./dist
USER nodejs
EXPOSE 5000
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD curl -f http://localhost:5000/health || exit 1
ENTRYPOINT ["dumb-init", "--"]
CMD ["node", "dist/index.js"]

4.3 Backend CORS middleware (CRITICAL!)

Vì FE và BE khác origin (example.com vs api.example.com), backend BẮT BUỘC phải có CORS middleware. Đây là phần quan trọng nhất khác biệt với version cũ.

// backend/src/index.ts
import express from 'express';
import cors from 'cors';

const app = express();

// CORS — phải đặt TRƯỚC mọi routes
app.use(cors({
  // CORS_ORIGIN sẽ đọc từ SSM Parameter Store qua backend/.env
  // Production: "https://example.com"
  // Local dev:  "http://localhost:5173"
  origin: process.env.CORS_ORIGIN || "http://localhost:5173",
  credentials: true,
  // Allow methods cho REST API
  methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE', 'OPTIONS'],
  // JWT token được gửi qua header này
  allowedHeaders: ['Content-Type', 'Authorization'],
}));

app.use(express.json({ limit: '5mb' }));
// ... routes

app.listen(5000);
⚠️ KHÔNG dùng origin: '*' Khi credentials: true, browser refuse wildcard. Phải là exact string trùng với protocol + domain (không trailing slash).
✅ Multiple origins (vd staging + production) 
origin: ['https://example.com', 'https://staging.example.com'],
Hoặc function: 
origin: (origin, callback) => {
  const allowed = ['https://example.com', 'http://localhost:5173'];
  callback(null, !origin || allowed.includes(origin));
}

Install cors package nếu chưa có:

cd backend
npm install cors
npm install --save-dev @types/cors

4.5 nginx/default.conf (chỉ proxy API)

Trên EC2, nginx chỉ làm 2 việc: terminate HTTPS cho api.example.com và proxy /api/* đến backend container. KHÔNG còn serve frontend.

# nginx/default.conf
# HTTP redirect lên HTTPS
server {
    listen 80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}

# HTTPS server cho API
server {
    listen 443 ssl http2;
    server_name api.example.com;

    # SSL certificate từ Let's Encrypt (Certbot)
    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # Cho phép upload file lớn (vd ảnh)
    client_max_body_size 50M;

    # Proxy /api/* đến backend container
    location /api/ {
        proxy_pass         http://backend_srv;   # Giữ nguyên prefix /api/
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 90s;
    }

    # Health check cho monitoring
    location /health {
        proxy_pass http://backend_srv;
    }

    # Mọi path khác → 404 (nginx không serve FE nữa)
    location / {
        return 404 "Not Found";
    }
}

upstream backend_srv {
    server backend:5000;
}

import axios from 'axios';

// VITE_API_URL được inject ở build time bởi GitHub Actions
// Production: "https://api.example.com"
// Local dev:  "http://localhost:5000" (set trong .env.local)
const rawApiUrl = (import.meta.env.VITE_API_URL ?? '') as string;
// Strip trailing /api nếu có để tránh double prefix
const baseURL = rawApiUrl.replace(/\/api\/?$/, '');

const api = axios.create({
  baseURL,
  timeout: 30000,
});

// Attach JWT token vào mọi request
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

export default api;

// Cách dùng:
// api.post('/api/auth/login', { email, password })
// → POST https://api.example.com/api/auth/login

    name: Build & Push to ECR

    outputs:
      image_tag: ${{ steps.tag.outputs.tag }}

      - uses: actions/checkout@v4

        with:
          aws-access-key-id:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region:            ${{ env.AWS_REGION }}

      - name: Set image tag
        id: tag
        run: echo "tag=${GITHUB_SHA::7}" >> $GITHUB_OUTPUT

      - name: Build & push backend image
        env:
          ECR_REGISTRY: ${{ secrets.ECR_REGISTRY }}
        run: |
          docker build -t $ECR_REGISTRY/myapp-backend:${{ steps.tag.outputs.tag }} ./backend
          docker push    $ECR_REGISTRY/myapp-backend:${{ steps.tag.outputs.tag }}
          docker tag     $ECR_REGISTRY/myapp-backend:${{ steps.tag.outputs.tag }} $ECR_REGISTRY/myapp-backend:latest
          docker push    $ECR_REGISTRY/myapp-backend:latest

    name: Deploy to EC2
    runs-on: ubuntu-latest
    needs: build

    steps:
      - uses: actions/checkout@v4

      - uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region:            ${{ env.AWS_REGION }}

      # Fetch tất cả /myapp/production/* vào backend/.env
      - name: Fetch secrets from Parameter Store
        run: |
          mkdir -p backend
          aws ssm get-parameters-by-path \
            --path "/myapp/production/" \
            --with-decryption \
            --query "Parameters[*].[Name,Value]" \
            --output text | \
          awk -F'\t' '{n=split($1,a,"/"); print a[n]"="$2}' > backend/.env
          echo "PORT=5000" >> backend/.env
          echo "NODE_ENV=production" >> backend/.env

      - name: Copy config to EC2
        uses: appleboy/scp-action@v0.1.7
        with:
          host:     ${{ secrets.EC2_HOST }}
          username: ubuntu
          key:      ${{ secrets.EC2_SSH_KEY }}
          source:   "docker-compose.prod.yml,nginx/default.conf,backend/.env,backend/init.sql"

          username: ubuntu

            cd ~/app
            aws ecr get-login-password --region ap-southeast-1 | \
              docker login --username AWS --password-stdin ${ECR_REGISTRY}

            ECR_REGISTRY=${ECR_REGISTRY} IMAGE_TAG=${IMAGE_TAG} \
              docker compose -f docker-compose.prod.yml pull
            ECR_REGISTRY=${ECR_REGISTRY} IMAGE_TAG=${IMAGE_TAG} \
              docker compose -f docker-compose.prod.yml down --remove-orphans || true
            ECR_REGISTRY=${ECR_REGISTRY} IMAGE_TAG=${IMAGE_TAG} \

        with:
          aws-access-key-id:     ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region:            ${{ env.AWS_REGION }}

      - name: Fetch VITE_API_URL from SSM
        run: |
          VITE_API_URL=$(aws ssm get-parameter \
            --name "/myapp/production/VITE_API_URL" \
            --query "Parameter.Value" --output text)
          echo "VITE_API_URL=$VITE_API_URL" >> $GITHUB_ENV

      - name: Build frontend
        working-directory: frontend
        env:
          VITE_API_URL: ${{ env.VITE_API_URL }}
        run: |
          npm ci
          npm run build

      - name: Sync dist to S3
        run: |
          # Static assets (hash filename) → cache 1 năm
          aws s3 sync frontend/dist/ s3://${{ env.S3_BUCKET }} \
            --delete \
            --cache-control "public,max-age=31536000,immutable" \
            --exclude "index.html"
          # index.html cache ngắn (60s) để user thấy update nhanh
          aws s3 cp frontend/dist/index.html s3://${{ env.S3_BUCKET }}/index.html \
            --cache-control "public,max-age=60"

      - name: Invalidate CloudFront
        run: |
          aws cloudfront create-invalidation \
            --distribution-id ${{ secrets.CLOUDFRONT_DISTRIBUTION_ID }} \
            --paths "/*"

# ============================================================
# morning.ps1 — Tạo EC2 mới, update DNS, deploy BE
# ============================================================

$REGION         = "ap-southeast-1"
$AMI            = "ami-02dd44faa40720bb8"   # Ubuntu 22.04 LTS ap-southeast-1
$INSTANCE_TYPE  = "t3.micro"
$KEY_NAME       = "deploy-ec2"
$SECURITY_GROUP = "sg-xxxxxxxxxxxxxxxx"     # Sửa: SG ID của bạn
$SUBNET_ID      = "subnet-xxxxxxxxxxxx"     # Sửa: Subnet ID
$IAM_PROFILE    = "myapp-ec2-role"
$HOSTED_ZONE_ID = "Z0XXXXXXXXXXXXXX"        # Sửa: Hosted zone ID
$DOMAIN_ROOT    = "example.com"             # Sửa: domain của bạn
$API_DOMAIN     = "api.$DOMAIN_ROOT"
$GITHUB_REPO    = "<org>/<repo>"            # Sửa: tên repo
$KEY_PATH       = "E:\AWS\deploy-ec2.pem"    # Sửa: đường dẫn key
$EMAIL          = "you@example.com"         # Sửa: email cho Let's Encrypt

# ─── 1. Tạo ECR repo (idempotent) ────────────────────
Write-Host "[1/5] Tạo ECR repo myapp-backend..." -ForegroundColor Cyan
aws ecr describe-repositories --repository-names myapp-backend --region $REGION 2>$null | Out-Null
if ($LASTEXITCODE -ne 0) {
    aws ecr create-repository --repository-name myapp-backend --region $REGION | Out-Null
}

# ─── 2. Launch EC2 ───────────────────────────────────
Write-Host "[2/5] Tạo EC2..." -ForegroundColor Cyan
$INSTANCE_ID = aws ec2 run-instances `
    --image-id $AMI `
    --instance-type $INSTANCE_TYPE `
    --key-name $KEY_NAME `
    --security-group-ids $SECURITY_GROUP `
    --subnet-id $SUBNET_ID `
    --iam-instance-profile "Name=$IAM_PROFILE" `
    --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=myapp-ec2}]' `
    --query "Instances[0].InstanceId" --output text --region $REGION

aws ec2 wait instance-running --instance-ids $INSTANCE_ID --region $REGION
$PUBLIC_IP = aws ec2 describe-instances --instance-ids $INSTANCE_ID `
    --query "Reservations[0].Instances[0].PublicIpAddress" --output text --region $REGION
Write-Host "    IP: $PUBLIC_IP" -ForegroundColor Green

# ─── 3. Update Route 53 api.example.com → IP mới ─────
Write-Host "[3/5] Update Route 53 + GitHub Secret..." -ForegroundColor Cyan
$CHANGE = '{"Changes":[{"Action":"UPSERT","ResourceRecordSet":{"Name":"' + $API_DOMAIN + '","Type":"A","TTL":60,"ResourceRecords":[{"Value":"' + $PUBLIC_IP + '"}]}}]}'
$tmpJson = [System.IO.Path]::GetTempFileName()
[System.IO.File]::WriteAllText($tmpJson, $CHANGE)
aws route53 change-resource-record-sets --hosted-zone-id $HOSTED_ZONE_ID --change-batch "file://$tmpJson" | Out-Null
Remove-Item $tmpJson -Force

# Refresh PATH để tìm gh
$env:PATH = [System.Environment]::GetEnvironmentVariable("PATH","Machine") + ";" + [System.Environment]::GetEnvironmentVariable("PATH","User")
gh secret set EC2_HOST --body $PUBLIC_IP --repo $GITHUB_REPO

# ─── 4. Wait + Setup EC2 (Docker, Certbot, SSL) ──────
Write-Host "[4/5] Đợi SSH ready (60s) + cài đặt..." -ForegroundColor Cyan
Start-Sleep -Seconds 60

$SETUP = @"
set -e
curl -fsSL https://get.docker.com | sh > /dev/null 2>&1
sudo usermod -aG docker ubuntu
sudo systemctl enable docker --now > /dev/null 2>&1

curl -s https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip -o awscliv2.zip
sudo apt-get install -y unzip > /dev/null 2>&1
unzip -q awscliv2.zip && sudo ./aws/install > /dev/null 2>&1
rm -rf aws awscliv2.zip

sudo apt-get install -y certbot > /dev/null 2>&1
sleep 60   # đợi DNS propagate
sudo certbot certonly --standalone -d $API_DOMAIN --non-interactive --agree-tos --email $EMAIL

mkdir -p ~/app
echo SETUP DONE
"@

$SETUP | ssh -i $KEY_PATH -o StrictHostKeyChecking=no ubuntu@$PUBLIC_IP "bash -s"

# ─── 5. Trigger deploy-backend workflow ──────────────
Write-Host "[5/5] Trigger deploy..." -ForegroundColor Cyan
gh workflow run deploy-backend.yml --ref main --repo $GITHUB_REPO

Write-Host "`n=== HOÀN THÀNH ===" -ForegroundColor Green

9. CORS — Tại sao và cấu hình

9.1 Tại sao đột nhiên cần CORS?

Phiên bản EC2/nginx cũ: FE và BE ở cùng example.com → same-origin → browser không kiểm tra CORS.

Phiên bản này: FE ở example.com, BE ở api.example.com → khác origin → browser enforce CORS policy của W3C để chống tấn công CSRF.

9.2 Cách CORS hoạt động

1. Simple request (GET, HEAD, POST với Content-Type cơ bản): Browser gửi thẳng request kèm header "Origin: https://example.com" Server phải trả về header: Access-Control-Allow-Origin: https://example.com Nếu không có header → browser block response (XHR error) 2. Preflight request (PUT, DELETE, hoặc custom headers như Authorization): Browser gửi TRƯỚC 1 request OPTIONS: OPTIONS /api/users/1 Origin: https://example.com Access-Control-Request-Method: DELETE Access-Control-Request-Headers: authorization,content-type Server phải trả về: Access-Control-Allow-Origin: https://example.com Access-Control-Allow-Methods: GET,POST,PUT,PATCH,DELETE,OPTIONS Access-Control-Allow-Headers: authorization,content-type Access-Control-Max-Age: 86400 (cache preflight 24h) Nếu OK → browser gửi request thật (DELETE) Nếu không OK → block, không gửi DELETE

9.3 Vì sao JWT đỡ phức tạp hơn cookie?

Cookie-based authJWT Bearer (project này)
Cách gửiBrowser tự attach cookieFE phải attach Authorization: Bearer

11. FAQ & Troubleshooting

11.1 CloudFront trả 504 Gateway Timeout

Nguyên nhân
  1. CloudFront chưa Deploy xong (status còn Deploying) → đợi
  2. S3 bucket policy chưa cho CloudFront đọc → check policy đã paste chưa
  3. OAC chưa associated → check distribution → tab Origins

11.2 React refresh ở /products trả 404

Custom Error Responses chưa tạo. Quay lại Section 5.7 step 6 tạo 404→index.html và 403→index.html (đều với status 200).

11.3 User vẫn thấy version FE cũ sau deploy

  1. Browser cache: Ctrl+Shift+R hard refresh
  2. CloudFront cache: chưa invalidate xong (mất 1-5 phút). Check workflow log có chạy invalidation chưa.
  3. Manual: aws cloudfront create-invalidation --distribution-id E2... --paths "/*"

11.4 ACM cert stuck ở "Pending validation" sau 30 phút

  1. Vào ACM → cert → tab Domains → xem CNAME validation records
  2. Route 53 → confirm các CNAME đã được tạo và đúng value
  3. nslookup -type=CNAME <validation-name>.example.com → DNS propagate?
  4. Nếu Route 53 chưa có CNAME: vào ACM → click "Create records in Route 53"
  5. Cuối cùng: delete cert và tạo lại

11.5 CORS error trong browser

Xem Section 9.4 — debug CORS.

11.6 GitHub Actions workflow fail ở step "Configure AWS credentials"

Lỗi The security token included in the request is invalid:

  1. GitHub Secret AWS_ACCESS_KEY_ID hoặc AWS_SECRET_ACCESS_KEY đã được thay/xoá trong AWS
  2. Vào IAM → deploy-bot → tạo Access key mới → cập nhật vào GitHub Secret
  3. Deactivate access key cũ trong IAM

11.7 deploy-frontend.yml fail ở step "npm ci"

Lỗi package-lock.json not in sync with package.json:

  1. Local: cd frontend; npm install; git add package-lock.json; git commit; git push
  2. Hoặc fallback: đổi npm ci thành npm install (chậm hơn, kém deterministic)

11.8 CloudFront delete bị block

Distribution phải Enabled = false + status = Deployed trước khi delete:

aws cloudfront wait distribution-deployed --id E2YYYYYYYYYY
$etag = aws cloudfront get-distribution --id E2YYYYYYYYYY --query "ETag" --output text
aws cloudfront delete-distribution --id E2YYYYYYYYYY --if-match $etag

11.9 SSH timeout khi morning.ps1 chạy step 4

EC2 chưa boot xong. Mặc định đợi 60s — nếu vẫn fail thử tăng lên 90-120s. Hoặc chạy setup-ec2.ps1 -IP <IP> sau đó retry.

11.10 Tại sao có 2 region (ap-southeast-1 và us-east-1)?

ACM cert cho CloudFront BẮT BUỘC ở us-east-1 (AWS-imposed). Tất cả thứ khác (S3, EC2, ECR, SSM) ở region chính (ap-southeast-1). Cross-region calls bị tính phí cực thấp ~$0.0001 nên không vấn đề gì.

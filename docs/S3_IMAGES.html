1. Tại sao cần S3 cho ảnh

Vấn đề trước khi migrate

  • Ảnh sản phẩm hardcode URL từ images.unsplash.com trong backend/src/data/mockData.ts — phụ thuộc bên thứ 3, có thể bị đổi hoặc remove.
  • Khi admin thêm sản phẩm mới, chỉ paste được URL hoặc base64 (UI cũ có file-upload nhưng đọc thành data: URL rồi bị submit handler bỏ qua → upload không hoạt động).
  • Không có nơi tin cậy để host ảnh nội bộ.

Giải pháp

  • S3 (private bucket) — lưu file, không cho public truy cập trực tiếp.
  • CloudFront trước S3 (qua OAC — Origin Access Control) — serve ảnh qua CDN, có HTTPS native, cache toàn cầu.
  • Presigned PUT URL — admin upload thẳng từ browser lên S3, không qua EC2 → tiết kiệm bandwidth/RAM/CPU EC2.
💡 Giá trị học S3 storage, CloudFront CDN, OAC (sigv4), bucket policy có condition, IAM instance profile, presigned URL với expiry, CORS cho cross-origin upload.

    "Name": "vhnlong-images-oac",
    "SigningProtocol": "sigv4",
    "SigningBehavior": "always",
    "OriginAccessControlOriginType": "s3"
  }'

{
  "Version": "2012-10-17",

    "Action": ["s3:PutObject", "s3:DeleteObject"],
    "Resource": "arn:aws:s3:::vhnlong-images/*"

}

# Tao policy va attach vao role co san cua EC2
aws iam create-policy --policy-name myapp-s3-images-write --policy-document file://.tmp-iam-policy.json
aws iam attach-role-policy `
  --role-name myapp-ec2-role `
  --policy-arn arn:aws:iam::529568113348:policy/myapp-s3-images-write
ℹ️ Vì sao chỉ cấp PutObject + DeleteObject? Backend không cần đọc S3 (CloudFront làm). Backend chỉ cần sign URL để FE upload. Least privilege — nếu code BE có bug RCE, attacker không dump được toàn bộ bucket.

4.3 Route presign (backend/src/routes/upload.ts)

import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';

// Tu dong dung credentials tu EC2 instance profile (khong can ACCESS_KEY)
const s3 = new S3Client({ region: env.S3_IMAGES_REGION });

router.post('/presign', authenticate, requireAdmin, asyncHandler(async (req, res) => {
  const filename    = requireString(req.body?.filename, 'filename', 255);
  const contentType = requireEnum(req.body?.contentType,
                          ['image/jpeg', 'image/png', 'image/webp'], 'contentType');

  const key = `products/${randomUUID()}.${EXT_BY_MIME[contentType]}`;

  const command = new PutObjectCommand({
    Bucket: env.S3_IMAGES_BUCKET,
    Key: key,
    ContentType: contentType,
  });

  const uploadUrl = await getSignedUrl(s3, command, { expiresIn: 300 }); // 5 phut
  const publicUrl = `${env.CDN_IMAGES_URL}/${key}`;

  res.json({ uploadUrl, publicUrl, key });
}));
ℹ️ Vì sao dùng UUID làm key? Tránh đè file (file cùng tên upload sau ghi đè file trước), và che giấu thông tin meta (số lượng ảnh / pattern). Tên file gốc lưu vào Metadata nếu cần debug.

5. Phase 3 — Frontend (upload UI)

5.1 Helper upload (frontend/src/api/endpoints/uploads.ts)

export async function uploadImage(file: File): Promise<string> {
  // Guards: type + size truoc khi tieu ton API call
  if (!ALLOWED_MIME.includes(file.type)) throw new Error(...);
  if (file.size > 10 * 1024 * 1024) throw new Error('Image too large');

  // 1. Goi BE xin presigned URL
  const { uploadUrl, publicUrl } = await uploadsApi.presign(file.name, file.type);

  // 2. PUT thang len S3 — KHONG qua BE
  const res = await fetch(uploadUrl, {
    method: 'PUT',
    body:   file,
    headers: { 'Content-Type': file.type },
  });
  if (!res.ok) throw new Error(`S3 upload failed: ${res.status}`);

  // 3. Tra ve URL public — luu vao DB
  return publicUrl;
}

5.2 Tích hợp trong AdminProducts.tsx

const handleFileChange = useCallback(async (e) => {
  const file = e.target.files?.[0];

  }

6. Phase 4 — Migrate ảnh unsplash sang S3

Script scripts/migrate-images-to-s3.ps1 làm 4 bước:

  1. Đọc mockData.ts + regex extract 14 URL unsplash duy nhất.
  2. Cho mỗi URL: Invoke-WebRequest tải về temp, aws s3 cp upload lên s3://vhnlong-images/products/seed-<hash12>.jpg. Hash từ URL gốc → re-run sẽ ra cùng key (idempotent).
  3. Tạo $mapping hashtable, gọi $content.Replace(oldUrl, newUrl) rồi Set-Content vào mockData.ts.
  4. Sinh ra backend/sql/migrate-images-s3.sql với 28 UPDATE statements (14 cho image, 14 cho images JSONB) — chạy trên prod DB qua psql trong container.
# Chay migration
.\scripts\migrate-images-to-s3.ps1

# Apply SQL len prod DB
scp -i $KEY backend/sql/migrate-images-s3.sql ubuntu@$EC2:/tmp/m.sql
ssh -i $KEY ubuntu@$EC2 "docker cp /tmp/m.sql myapp-production-db-1:/tmp/m.sql && `
  docker exec myapp-production-db-1 psql -U <user> -d <db> -f /tmp/m.sql"
⚠️ Lưu ý khi re-run migration Script idempotent về S3 keys (hash từ URL gốc) nhưng SQL không idempotent — nếu URL trong DB đã đổi sang CloudFront thì WHERE image = '<unsplash url>' sẽ match 0 row. Vẫn an toàn, chỉ là no-op.

8. Troubleshooting

"Access Denied" khi load ảnh qua CloudFront

  • Bucket policy thiếu hoặc sai SourceArn → check: aws s3api get-bucket-policy --bucket vhnlong-images
  • OAC chưa attach vào CloudFront origin → check trong distribution config: Origins[].OriginAccessControlId ≠ rỗng
  • Distribution status vẫn InProgress (5-15 phút) → đợi Deployed

"CORS error" khi FE PUT lên S3

  • CORS chưa apply: aws s3api get-bucket-cors --bucket vhnlong-images
  • Origin trong CORS không khớp domain FE (ví dụ chạy ở port khác)
  • Browser cache CORS preflight cũ → hard reload (Ctrl+Shift+R)

BE trả 500 khi gọi /api/upload/presign

  • EC2 chưa có IAM policy: aws iam list-attached-role-policies --role-name myapp-ec2-role
  • S3_IMAGES_BUCKET rỗng → check SSM param + backend/.env trên EC2
  • EC2 instance metadata bị disable → check IMDSv2: aws ec2 describe-instances --query "Reservations[].Instances[].MetadataOptions"

9. Cleanup khi học xong

# 1. Xoa tat ca object trong bucket (CloudFront khong xoa duoc bucket non-empty)
aws s3 rm s3://vhnlong-images --recursive --region ap-southeast-1

# 2. Disable + delete CloudFront distribution (15-20 phut)
# Phai disable truoc, doi den khi "Deployed", roi moi delete
aws cloudfront get-distribution-config --id E1IFEQXVGMUBI1 > cf.json
# sua "Enabled": false trong cf.json -> update -> doi -> delete

# 3. Xoa OAC
aws cloudfront delete-origin-access-control --id E3SD4BD63A1HXK --if-match <ETag>

# 4. Detach + xoa IAM policy
aws iam detach-role-policy --role-name myapp-ec2-role `
  --policy-arn arn:aws:iam::529568113348:policy/myapp-s3-images-write
aws iam delete-policy --policy-arn arn:aws:iam::529568113348:policy/myapp-s3-images-write

# 5. Xoa bucket
aws s3api delete-bucket --bucket vhnlong-images --region ap-southeast-1

# 6. Xoa SSM params
foreach ($e in 'production','staging') {
  aws ssm delete-parameter --name "/myapp/$e/S3_IMAGES_BUCKET"
  aws ssm delete-parameter --name "/myapp/$e/S3_IMAGES_REGION"
  aws ssm delete-parameter --name "/myapp/$e/CDN_IMAGES_URL"
}
🚨 Không xoá ngược thứ tự Bucket không xoá được khi còn object. CloudFront không xoá được khi còn enabled. IAM policy không xoá được khi còn attach vào role.
